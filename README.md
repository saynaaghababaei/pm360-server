# ارزیابی ۳۶۰ درجه PM — نسخه‌ی سرور

نسخه‌ی چندکاربره‌ی ابزار ارزیابی ۳۶۰ درجه‌ی PM دیجی‌پی — با لاگین مشترک، دیتابیس واقعی (Postgres)، و قابل‌دیپلوی رو Vercel. جایگزین نسخه‌های قبلی HTML تک‌فایلی (که هرکدام فقط رو مرورگر خودشان کار می‌کردند).

## معماری

- **Next.js 16** (App Router) + **TypeScript** + **Tailwind**
- **Prisma** + **PostgreSQL** برای دیتابیس
- لاگین با **رمز مشترک** (بدون حساب جدا برای هرکس) — کوکی امضاشده با HMAC
- منطق نمره‌دهی در `src/lib/scoring.js` — پورت مستقیم از نسخه‌ی نهایی HTML (v12)، با تست موازی برای اطمینان از یکسان‌بودن نتیجه

## راه‌اندازی محلی (برای توسعه)

```bash
npm install
# .env.example را به .env کپی کن و مقادیرش را پر کن
npx prisma migrate dev
npm run dev
```

## وضعیت فعلی — چه چیزی کامل است، چه چیزی نیست

### کامل و تست‌شده
- کل منطق نمره‌دهی: میانه‌ی گروهی، چندانتخابی، قانون رأی اکثریت مدیر/دایرکتور/معاون، الگوریتم تعیین سطح، ماتریس کامل مدل، برنامه‌ریزی توسعه، تفکیک ارزیاب — همه با تست خودکار در برابر نسخه‌ی HTML تایید شدند.
- لاگین با رمز مشترک (تست شد، مستقل از دیتابیس).
- قفل ترتیبی متقاضی به مدیر/دایرکتور/معاون.
- مثال STAR اختیاری، با نمایش به مدیر/دایرکتور/معاون.
- API کامل (CRUD ارزیابی، ارزیاب، پرسشنامه، گزارش).

### ساخته شده ولی در این محیط قابل‌اجرا/تست نبود
به‌خاطر محدودیت شبکه‌ی محیط توسعه (عدم دسترسی به سرورهای Prisma برای دانلود باینری موتور)، لایه‌ی دیتابیس (Prisma) را نتوانستم مستقیماً روی یک دیتابیس واقعی اجرا و تست کنم. کد بر اساس الگوهای استاندارد و مستندشده‌ی Prisma نوشته شده و باید بدون مشکل کار کند، ولی اولین اجرای واقعی (قدم ۵ و ۶ در DEPLOY.md) را حتماً خودتان دنبال کنید.

### هنوز به‌طور کامل پورت نشده (نسخه‌ی ساده‌شده در گزارش وب موجود است)
- درخت کامل ساب‌اسکیل در برنامه‌ریزی توسعه: در نسخه‌ی HTML، هر دسته با کلیک به Competency تا Skill تا SubSkill باز می‌شد و تعریف رفتار/رفتار واقعی/Strong Signal هر سطح نشان داده می‌شد. در این نسخه فعلاً فقط عنوان دسته و وضعیت نشان داده می‌شود.
- پنل ویرایش وزن‌های ارزیاب از داخل گزارش: در نسخه‌ی HTML قابل‌تغییر بود؛ در این نسخه فعلاً وزن‌ها فقط از تنظیمات پیش‌فرض خوانده می‌شوند.
- صفحه‌ی راهنما خلاصه‌شده است (۱۳ بخش کلیدی، نه متن کامل تمام جزئیات نسخه‌ی HTML).

اگر هرکدام از این‌ها برایتان ضروری است، بگویید تا در دور بعدی کامل شوند.
